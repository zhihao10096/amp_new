## 3. 随机初始化 AMP 三轮失败：分别尝试了什么

### 3.1 R1：先检验是否只是训练时间不够

第一轮从随机初始化直接训练速度、最终步态奖励和 AMP。1000 轮时摔倒很多，但风格距离已有改善，actor 实际更新也较少，因此先保持配置继续到 3000，保存并完整评估 1000/2000/3000。

结果是 2000 轮倾向稳定站立，3000 轮稳定性又退化。继续训练没有产生有效迈步，所以停止原配置续训，不能再只用“时间不够”解释失败。

### 3.2 R2：减慢过强的判别器

发现判别器几乎完全区分策略与专家：策略分数接近 `-1`，真实风格奖励约 `.003`。

参考上游同症状 Issue，新增可配置更新间隔，将 G1 判别器改为：

- 每 5 个训练迭代更新一次，每次仍做 2 个 D 更新；
- 学习率由 `1e-4` 降到 `1e-5`；
- 梯度惩罚由 10 增到 40；
- 最终 AMP 权重等其他任务条件保持不变。

更新计数、CLI 恢复和旧模型兼容验证通过。新随机实验的 D 信号有所改善，但策略仍原地站立。**节流 D 有优化层面的效果，没有解决行走。**

### 3.3 R3：加大真实探索

真实噪声诊断发现，OU 噪声 `.3→.6` 能将单脚支撑比例由约 `5.75%` 提高到 `20.93%`，接触变化由约 `1.17` 提高到 `3.35` 次/秒，但摔倒也增加。较大的 Gaussian 噪声导致双脚腾空过多，没有采用。

R3 仅将 OU 幅度改为 `.6`，仍让 25% 环境使用 OU、其余使用 Gaussian `.1`。与 R2 核对相同随机初值，重新训练到 3000。

结果：增加了采样覆盖，但没有学会有效迈步。**“覆盖更多动作”和“形成步态”没有同时实现。**

### 3.4 三轮最终检查点的实际结果

下表摔倒数仅指各轮 3000 检查点的**固定指令速度评估**，不混入随机组或七指令步态评估。

| 实验 | 主要变化 | 固定总体 RMSE：vx / vy / yaw | 固定评估摔倒 | 0.6 m/s 每足步频 | 结论 |
|---|---|---|---:|---:|---|
| R1 | 原始随机 AMP，延长到 3000 | `.623 / .308 / .340` | 159 | .016 Hz | 接近零，未形成有效步态 |
| R2 | D 更新节流、降低学习率、提高 GP | `.637 / .226 / .410` | 52 | 0 Hz | D 改善，行走未改善 |
| R3 | 在 R2 基础上将 OU `.3→.6` | `.630 / .240 / .390` | 63 | 0 Hz | 覆盖增加，仍原地站立 |

R2 的留出风格距离相对初始改善约 `41.8% / 46.5%`，R3 改善约 `59.2% / 59.0%`，但均不走。**风格距离改善不能单独选出合格行走模型。**

R1 的 `.016 Hz` 来自实际接触事件统计，不能精确写成 0；这一极低频率仍不构成有效行走。原始步态证据为 `logs/amp_g1/formal_r1_gait3000.json`。

三轮是不同的随机来源实验，不能将它们各自 3000 轮相加，称为同一策略已经训练 9000 轮。

证据：`formal_r1_assessment1000/2000/3000.json`、`formal_r2_summary.json`、`formal_r3_summary.json`、`discriminator_throttle_validation.audit.json`、`noise_coverage_r2.json`，均在 `logs/amp_g1/` 下。

## 4. 为定位原地站立，排查过哪些方向

| 疑点 | 做过的检查或处理 | 实际效果与结论 |
|---|---|---|
| 参考重置是否严重穿地、引发冲量 | 对同一批参考帧比较根高度偏移 `0/.05/.1 m` | 原始高度下脚 link 最低约 `.02735 m`，首 `.4 s` 无摔倒；加 `.1 m` 反而引入更大的自由落体。没有支持严重穿透假设，保留原高度 |
| 参考关节轨迹能否直接产生可用动态数据 | 在 PhysX 中施加连续参考 PD、PD 加关节速度前馈，以及固定参考关节目标；只在初态写状态 | 2 秒内约 `127–128/128` 摔倒，未接入正式采样。不能直接把离线参考角度变成稳定控制器 |
| 高 D 分数是否意味着动作正确 | 比较真实控制结果与风格分数；对冻结 D 做静止、交换帧、打乱帧等反事实探针 | 固定参考关节目标控制会摔倒却获高 style；清零速度并重复姿态的离线特征仍获 `.874` 左右，正常专家约 `.890`。说明当前信号对运动/时序区分不足，但不能据此断言 D 完全只看姿态 |
| 是否骨架、关节顺序或足端几何映射错误 | 从本项目 USD 提取正运动学，与七份训练参考及真实 PhysX 状态核对 | 参考世界位置 RMSE `<3.2e-7 m`，真实足端位置最大误差 `6.03e-6 m`。严重几何映射错误没有得到支持 |
| 用 FK 强制替换 WM 足端预测是否更好 | 比较 WM 自由足端通道与由其关节角推得的足端位置 | 32 步实际足端误差仅由约 `12.71 mm` 变为 `12.59 mm`；收益不足，未加入 WM 投影结构 |
| 普通站立状态 WM 是否整体失效 | 比较真实与想象轨迹、回报及生存率 | 普通状态短程差异不大，不支持“WM 全面爆炸”；结论限于已测状态和指令，不能排除动态分布误差 |
| 最初动作响应实验是否可信 | 加入零扰动对照、复制初态、共同接触预热 | 最初普通站立复制状态的接触求解差异与动作信号同量级，不能凭它宣称 WM 梯度错误；后续使用共同预热后的成对实验 |

其中“固定参考关节目标控制”并不等于机器人完全静止：机身仍会移动、失稳。这一点已在后续记录中纠正。

## 5. 动力学和价值学习：有局部改善，但没有闭环收益

### 5.1 补动态数据并重新拟合世界模型

问题假设是：站立策略采集不到足够单支撑和落脚数据，导致 WM 在动态状态上不准确。

补充真实动态数据后，独立初态 8 步线速度预测 RMSE 由 `.29988` 降到 `.14465 m/s`，约改善 51.8%。但同初态的真实 MPC 平均存活由 `1.2669 s` 降到 `.9331 s`，两组均 `32/32` 摔倒。

**效果：预测更准，控制没有更稳。该诊断 WM 未作为正式策略或正式采样修复接入。**

### 5.2 增加成对动作响应约束

进一步区分“状态预测正确”和“动作改变时预测方向正确”。在相同真实初态、共同预热和成对动作分支下，拟合动作响应，保留独立初态做验证。

| 指标 | 原 WM | 普通拟合 | 加响应约束 |
|---|---:|---:|---:|
| 8 步线速度 RMSE，m/s | `.0767` | `.0591` | `.0317` |
| 8 步速度响应方向余弦 | `.685` | `.685` | `.784` |
| 匹配预热后 MPC 平均存活，s | `.9550` | `.9725` | `.90125` |
| 匹配预热后 2 秒摔倒 | `16/16` | `16/16` | `16/16` |

**效果：局部预测和响应改善，仍没有稳定的真实控制收益。** 当前 MPC/响应拟合方向停止作为优先采样修复方案。该结论不等于已证明所有 WM 梯度都正确。

### 5.3 检查真实与想象价值，并尝试真实 TD 锚定

冻结 R3 actor、critic、WM、D，对相同初态比较 32 步、带相同旧 critic 尾项的回报：

| 初态 | 真实 bootstrap 回报 | 想象 bootstrap 回报 |
|---|---:|---:|
| 普通 reset | `3.0379` | `3.0895` |
| 参考 RSI | `1.1229` | `.8656` |

普通状态接近，参考动态状态反而偏保守。因此没有证据支持简单的“想象收益普遍过度乐观”解释。这也不是完整 Monte Carlo 真实价值估计。

随后新增可选 `critic_real_fraction`，固定 critic 总样本预算，将一半目标换为真实一步 TD；actor 始终通过 WM 可微想象更新，不使用 PPO。

实现验证通过：正确区分摔倒/超时、使用终止前状态、跳过命令切换、独立 RNG 保存恢复，默认关闭时与旧更新逐位一致。闭环对照从同一 R3 `model_3000` 各续训 500 轮：

| 方案 | 固定总体 RMSE：vx / vy / yaw | 固定评估摔倒 | 七指令步态 |
|---|---|---:|---|
| 真实 TD 比例 0 | `.6422 / .2238 / .3938` | 53 | 每足步频均 0 |
| 真实 TD 比例 .5 | `.6335 / .2406 / .3831` | 58 | 每足步频均 0 |

**效果：实现正确，但本次对照没有迈步收益，未设为默认，也不继续盲目加码。**

证据：`dynamic_coverage_r3_*.json`、`directional_response_r3.json`、`response_fit_r3.json`、`response_warm_control_r3_control_*.json`、`policy_value_r3.json`、`real_value_validation.audit.json`、`real_value_ablation.pipeline.json`。

## 6. 真正改变结果的阶段：对齐 Go2 冷启动过程

### 6.1 先纠正 A1 与 G1 比较的起点

A1 AMP 正式训练并不是从完全随机的行走策略开始：其 `model_0` 的 actor/WM 与已收敛 Go2 Manager 模型逐张量一致。

AMP 第 0 轮，A1 已在 1.0/1.5 m/s 指令下达到约 `.941/1.434 m/s`，七组测试零摔倒；G1 R3 随机 `model_0` 的七组测试共 806 次摔倒、步频为 0。

这解释了 A1 为什么能很快进入 AMP 风格学习，但**不能解释全部 G1 失败**，因为 Go2 确实能够从零成功。

### 6.2 找到 G1 没有复现 Go2 奖励课程的具体代码差异

Go2 先使用弱初期正则，再于 3000→5000 逐渐引入最终步态要求。G1 早期直接使用最终 walk 奖励，还存在两处课程接口缺口：

1. `g1.reward` 没有读取 `joint_deviation_gait_fraction`，关节偏移一直采用最终 L1 项。
2. G1 特有的 `flight`、`feet_distance` 没有随课程调度。

小偏移 `.01 rad` 时，G1 原 L1 项相对 Go2 初期平方项，单关节局部代价为 60 倍、非零点梯度幅度为 30 倍。这是该局部项的比较，不能扩大成整个奖励或 actor 梯度的倍率。

处理方式：

- 增加 `G1-Velocity-Flat`，共享 G1 资产、动作、奖励、PD 和 SuperMimic，只关闭 AMP。
- 修复课程：初期使用平方关节惩罚，逐渐切换至最终 L1；G1 特有项同步插值。
- 从 G1 自身随机初始化建立基础运动，再考虑同机器人 actor/WM 的 AMP 热启动。

相关提交：`bfa649a`、`9b77f25`。

### 6.3 从零基础阶段的实际变化

## 7. 已经会移动后，为什么 AMP 还没有把步态修好

### 7.1 原 61 维特征缺少直接运动信息

原 G1 每帧 AMP 特征只有角速度、29 个关节角、29 个关节速度。它没有直接观察根线速度、足端位置或根高度。

检查发现，在离线状态中只改变根线速度、高度、重力或足端通道时，原特征和 D 分数不变。此检查证明直接可辨识性缺失，不代表真实轨迹中关节与这些变量完全独立。

因此先测已有 61 维，再单独增加根线速度，形成 64 维 `g1_amp_64_velocity_v1`。真实、参考、想象均统一机体系速度；保留默认 61 维兼容和 checkpoint metadata。实现提交 `e375093`，当时 CPU 58 项通过。

### 7.2 同源 1000 轮四臂诊断

四臂都从同一 G1 速度 `model_9000` 继承 actor/WM 及归一化，重建 critic/优化器；AMP 臂另建 D。训练均使用 18432 环境及相同学习批次。70 维与 64 维逐字段核对，只变更实验名称和特征 schema；70 维初始 actor/critic/WM 与 64 维逐张量一致，actor/WM 与 9000 来源一致，优化器初始状态为空。

## 8. 奖励“可导”问题，实际核对结果是什么

**Go2 与 G1 都不是每个奖励项都处处光滑，也不是在所有状态都有非零梯度。**

| 项目 | 当前性质 | 对训练的含义 |
|---|---|---|
| 指数速度跟踪、姿态、高度、平方动作变化 | 连续可导 | 可通过 WM 反传，但误差过大等情况下梯度仍可能很弱 |
| L1、`min/max`、关节限位、电机限幅、`clamp` | 分段可导 | PyTorch 使用相应导数/次梯度；饱和或不激活区域可为 0 |
| 是否有运动指令 | 对指令的布尔门控 | 指令是外部条件，不提供动作方向梯度；门控之内的连续项仍可导 |
| Go2 关节惩罚中的实际速度阈值 | 对状态的布尔切换 | 不会对“跨过这个阈值”本身求导；其余连续路径仍在 |
| 真实 PhysX 接触、摔倒 | 离散事件 | 不通过真实物理事件直接反传 |
| 想象接触和终止 | 连续接触值经 `clamp + smoothstep`；终止用 sigmoid | 为计时、生存及终止奖励提供近似梯度；clamp 饱和时仍可能为 0 |
| AMP 风格奖励 | 保留对输入状态的梯度，D 参数在 actor 更新时冻结 | 可经 D→状态→WM→动作反传；风格 clamp 或特征不足仍可能限制效果 |

一个已直接验证的缺口是现有脚高奖励：

```text
exp(-Σ[(足高 - 目标足高)² × tanh(2 × 足端水平速度)] / variance)
```

脚的水平速度为 0 时，对脚高的梯度为 0，而且该项会给最大值。它适合约束已经摆动的脚，不能指望这一项独自诱导第一次抬脚。

Go2/A1 也有类似公式，不能把它当成 G1 独有错误；Go2 的早期课程和 A1 的已有运动能力改变了它们面对的训练阶段。当前尚未通过奖励单变量对照证明这是剩余碎步的唯一根因。

核对代码：`go2_supermimic/g1.py`、`velocity.py`、`amp.py`、`supermimic/imagine.py`。
